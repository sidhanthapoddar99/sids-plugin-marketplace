# database — schema owner

Every schema change starts here. One folder per engine.

| Folder | Holds | Applied by |
|---|---|---|
| `postgres/` | Alembic: `alembic.ini`, `migrations/versions/`, its own `pyproject.toml`, and the `Dockerfile` of the `migrate` one-shot | the `migrate` service in `docker/compose.db.yaml`, run by `ctl db migrate` and whenever the engines come up |
| `neo4j/` | `init.cypher` — constraints and indexes, idempotent | the `neo4j-init` service, the same way |
| `redis/` | `redis.conf` | mounted read-only by `compose.db.yaml` |

Both one-shots run inside the compose network, so no engine port is published for them. The apps
wait on them with `condition: service_completed_successfully` and never migrate on their own boot.

Two backends read Postgres, and the schema uses partial and GIN indexes, pgvector and triggers —
so revisions are hand-written, not autogenerated. `ctl db migrate new "<msg>"` creates one.
